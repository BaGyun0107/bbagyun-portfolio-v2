# Feature Specification: 연결형 스윔레인 재설계

**Feature Branch**: `chore/cleanup-downstream-harness`

**Created**: 2026-08-20

**Status**: Draft

**Input**: User description: "하네스 작업물의 현재 스윔레인은 전체 흐름을 이해하기 어렵다. 참고 이미지처럼 책임 주체 사이의 이동, 의사결정과 되돌림이 실제로 연결된 교차 기능 스윔레인으로 바꾸고 각 흐름은 핵심 단계로 묶는다. 지표의 '제한' 표현도 문맥에 맞는 범위 표현으로 바꾼다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 설계부터 검증까지 전체 흐름 추적 (Priority: P1)

면접관은 하네스가 사용자 요청을 어떻게 문제 정의, 계획, 승인, 구현과 검증으로
연결하는지 하나의 흐름으로 파악하고 싶다. 단계가 책임 주체별로 흩어진 카드가 아니라
실제 연결선으로 이어져야 어디서 다음 주체로 넘어가고 언제 이전 단계로 돌아가는지
이해할 수 있다.

**Why this priority**: 이 흐름은 실행 데모를 제공할 수 없는 하네스에서 설계·개발 운영
방식을 설명하는 핵심 증거다.

**Independent Test**: `설계·개발·검증` 다이어그램만 보고 네 책임 주체와 핵심 여섯
단계, 세 가지 예외 상황의 복귀 지점을 순서대로 설명할 수 있다.

**Acceptance Scenarios**:

1. **Given** 방문자가 설계·개발·검증 다이어그램을 처음 볼 때, **When** 정상 화살표를 위에서 아래로 따라가면, **Then** 요청·맥락 전달, 문제 정의, 명세·계획, 승인, 테스트·구현, 리뷰·검증의 여섯 단계를 순서대로 확인한다.
2. **Given** 정상 흐름이 서로 다른 책임 주체로 이동할 때, **When** 연결선을 따라가면, **Then** 사용자, AI 에이전트, 계획·구현, 리뷰·검증 중 누가 해당 단계를 담당하는지 식별한다.
3. **Given** 요구의 모호성, 계획 미승인 또는 검증 실패가 있을 때, **When** 예외 경로를 따라가면, **Then** 어느 단계로 돌아가고 무엇을 보강한 뒤 다시 진행하는지 이해한다.

---

### User Story 2 - 변경부터 배포까지 책임 경계 추적 (Priority: P1)

면접관은 코드 변경이 품질 검사, 환경과 대상 결정, 시크릿 조회와 배포로 이어지는
과정에서 각 시스템이 맡는 책임과 배포가 시작되지 않는 조건을 한눈에 보고 싶다.

**Why this priority**: 하네스의 배포 가치는 특정 도구 이름보다 검증되지 않은 변경이나
잘못된 환경 값이 배포로 넘어가지 못하게 하는 책임 경계에 있다.

**Independent Test**: `CI/CD·시크릿·배포` 다이어그램만 보고 네 책임 주체와 핵심 여섯
단계, 품질·시크릿 실패 시 중단 및 재실행 흐름을 설명할 수 있다.

**Acceptance Scenarios**:

1. **Given** 저장소 변경이 발생했을 때, **When** 방문자가 정상 화살표를 따라가면, **Then** 변경 감지, 품질 검사, 환경·대상 결정, 시크릿 조회, 병렬 배포, 결과 확인의 여섯 단계를 순서대로 확인한다.
2. **Given** 품질 검사가 실패했을 때, **When** 예외 경로와 대응 설명을 확인하면, **Then** 시크릿 조회와 배포가 시작되지 않음을 이해한다.
3. **Given** 환경이나 시크릿이 일치하지 않을 때, **When** 예외 경로와 대응 설명을 확인하면, **Then** 배포를 중단하고 설정을 수정한 뒤 전체 흐름을 처음부터 다시 실행함을 이해한다.

---

### User Story 3 - 결과 수치의 해석 범위 이해 (Priority: P2)

면접관은 핵심 결과 카드의 부가 설명이 성과의 막연한 `제한`인지, 비용 산정 범위인지,
실제 측정 범위인지, 운영 관찰 범위인지 혼동하지 않고 싶다.

**Why this priority**: 측정값·보고값·추정값의 근거를 구분하더라도 같은 `제한` 문구를
사용하면 수치가 의미하는 범위를 정확히 전달하기 어렵다.

**Independent Test**: 추정값, 측정값과 사용자 보고값이 각각 산정 범위, 측정 범위와
관찰 범위로 표시되고 기존 `제한:` 문구가 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 외부 가격으로 계산한 추정값에 보충 설명이 있을 때, **When** 결과 카드를 읽으면, **Then** 해당 설명을 `산정 범위`로 인식한다.
2. **Given** 실행 결과를 비교한 측정값에 보충 설명이 있을 때, **When** 결과 카드를 읽으면, **Then** 해당 설명을 `측정 범위`로 인식한다.
3. **Given** 운영 관찰에 기반한 보고값에 보충 설명이 있을 때, **When** 결과 카드를 읽으면, **Then** 해당 설명을 `관찰 범위`로 인식한다.

---

### User Story 4 - 화면과 관계없이 같은 흐름 이해 (Priority: P2)

키보드 또는 보조 기술을 사용하는 방문자는 시각 연결선을 직접 해석하지 못하더라도
동일한 전체 흐름과 예외 대응을 이해하고 싶다. 작은 화면을 사용하는 방문자는 페이지
전체가 옆으로 밀리지 않은 상태에서 다이어그램 영역만 탐색하고 싶다.

**Why this priority**: 스윔레인은 장식이 아니라 데모를 대신하는 핵심 콘텐츠이므로
화면 크기나 시각 정보 접근 여부와 관계없이 의미가 보존돼야 한다.

**Independent Test**: 다이어그램을 보지 않고 전체 흐름 설명과 예외 상황 문장만 읽어도
두 프로세스를 설명할 수 있고, 지원 화면 너비에서 키보드로 다이어그램 영역만 가로
탐색할 수 있다.

**Acceptance Scenarios**:

1. **Given** 방문자가 시각 다이어그램을 사용할 수 없을 때, **When** 전체 흐름 설명과 예외 상황을 읽으면, **Then** 시각 다이어그램과 동일한 정상 순서와 대응 결과를 이해한다.
2. **Given** 다이어그램이 화면보다 넓을 때, **When** 키보드 사용자가 이름 있는 다이어그램 영역에 초점을 두고 좌우 방향키를 사용하면, **Then** 페이지 전체가 아니라 해당 다이어그램만 가로 이동한다.
3. **Given** 방문자가 키보드로 상세 페이지를 탐색할 때, **When** 스윔레인에 도달하면, **Then** 정적인 단계와 연결선 때문에 불필요한 정지점이 추가되지 않는다.

### Edge Cases

- 책임 주체 또는 단계 ID가 중복되거나 단계가 존재하지 않는 책임 주체를 참조하면 게시 가능한 흐름으로 취급하지 않는다.
- 같은 책임 주체의 같은 진행 위치에 두 단계가 배치되면 겹치는 데이터로 판단해 게시를 차단한다.
- 시작 또는 완료 지점이 없거나 둘 이상이면 전체 흐름이 불명확하므로 게시를 차단한다.
- 시작부터 완료까지 이어지는 정상 경로가 없으면 다이어그램을 게시하지 않는다.
- 연결이 존재하지 않는 단계를 참조하거나 좌표가 유효한 수가 아니면 게시를 차단한다.
- 예외 경로에 방문자가 이해할 수 있는 발생 조건과 대응 문장이 없으면 게시를 차단한다.
- 예외가 없는 작업물에는 빈 `예외 상황과 대응` 영역을 만들지 않는다.
- 보충 설명이 없는 지표에는 빈 산정·측정·관찰 범위 영역을 만들지 않는다.
- 다이어그램이 작은 화면보다 넓어도 상세 페이지 전체 너비를 늘리지 않는다.
- 다크 모드에서도 정상선과 예외선, 단계와 의사결정 도형을 구분할 수 있어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 하네스 상세는 `설계·개발·검증`과 `CI/CD·시크릿·배포`를 서로 분리된 두 개의 교차 기능 스윔레인으로 제공해야 한다.
- **FR-002**: 각 스윔레인은 책임 주체를 세로 영역으로 구분하고 진행 방향을 위에서 아래로 일관되게 제공해야 한다.
- **FR-003**: `설계·개발·검증` 흐름은 요청·맥락 전달, 문제 정의, 명세·계획, 승인, 테스트·구현, 리뷰·검증의 핵심 여섯 단계를 제공해야 한다. `리뷰·검증`은 통과·실패를 판정하는 단계이며, 통과선 뒤의 보조 `완료` 종점은 핵심 여섯 단계 수에 포함하지 않는다.
- **FR-004**: `CI/CD·시크릿·배포` 흐름은 변경 감지, 품질 검사, 환경·대상 결정, 시크릿 조회, 병렬 배포, 결과 확인의 핵심 여섯 단계를 제공해야 한다.
- **FR-005**: 모든 정상 단계는 방문자가 시작부터 완료까지 끊김 없이 추적할 수 있는 방향성 연결로 이어져야 한다.
- **FR-006**: 작업 단계, 의사결정, 시작·완료와 중단은 서로 다른 도형 또는 명시적 문구로 구분돼야 한다.
- **FR-007**: 정상 진행과 중단·되돌림은 색상 외에 서로 다른 선 스타일과 문구로 구분돼야 한다.
- **FR-008**: 설계·개발·검증 흐름은 모호성, 계획 미승인, 검증 실패의 발생 조건과 복귀 대상을 제공해야 한다.
- **FR-009**: CI/CD·시크릿·배포 흐름은 품질 검사 실패와 환경·시크릿 불일치 시 배포 중단 범위 및 재실행 대상을 제공해야 한다.
- **FR-010**: 공개 화면은 내부 데이터 용어인 `연결과 분기`, `순서형 대체 설명`, `이전 단계로 복구`, `계속`을 흐름 설명 제목이나 결과 문구로 노출하지 않아야 한다.
- **FR-011**: 각 스윔레인은 시각 흐름과 동일한 정상 순서를 설명하는 `전체 흐름 설명`을 제공해야 한다.
- **FR-012**: 예외가 있는 스윔레인은 `예외 상황과 대응`을 발생 조건과 완성된 대응 문장으로 제공하고, 예외가 없으면 해당 영역을 생략해야 한다.
- **FR-013**: 지표 보충 설명은 추정값의 `산정 범위`, 측정값의 `측정 범위`, 사용자 보고값의 `관찰 범위`로 표시해야 한다.
- **FR-014**: 공개 화면은 핵심 결과 카드에서 일반적인 `제한:` 문구를 노출하지 않아야 한다.
- **FR-015**: 각 다이어그램은 보조 기술이 식별할 수 있는 고유한 이름과 전체 흐름 설명을 가져야 한다.
- **FR-016**: 넓은 다이어그램은 자체 영역에서 키보드로 가로 탐색 가능해야 하며 정적 단계와 연결은 개별 키보드 정지점을 만들지 않아야 한다.
- **FR-017**: 320px, 768px, 1024px와 1440px 화면에서 상세 페이지 전체 가로 넘침이 발생하지 않아야 한다.
- **FR-018**: 공개 전에 중복 ID·위치, 잘못된 책임 주체·단계·연결 참조, 유효하지 않은 위치, 시작·완료 누락, 단절된 정상 경로와 설명 없는 예외를 차단해야 한다.
- **FR-019**: 하네스에 공개 데모 또는 준비 중 CTA를 추가하지 않아야 한다.
- **FR-020**: 하네스 외 7개 작업물의 기존 본문과 공개 경로는 변경 없이 유지해야 한다.
- **FR-021**: 이번 변경은 이후 인터뷰가 완료된 작업물에서도 같은 흐름 규칙을 사용할 수 있어야 한다.
- **FR-022**: 모든 행동 변경은 실패하는 계약 또는 사용자 흐름 테스트를 먼저 확인한 뒤 구현해야 한다.

### Key Entities

- **스윔레인**: 목적, 책임 주체, 시작부터 완료까지의 정상 흐름, 예외 상황과 전체 흐름 설명을 가진 프로세스 증거다.
- **책임 주체**: 프로세스의 특정 단계를 담당하며 다이어그램에서 독립된 세로 영역을 차지한다.
- **흐름 단계**: 책임 주체, 진행 위치, 도형 의미, 표시 문구와 설명을 가진 작업 또는 의사결정 지점이다.
- **흐름 연결**: 시작 단계, 도착 단계, 정상·예외 구분, 진행 결과와 선택 경로를 가진 방향성 관계다.
- **예외 대응**: 하나 이상의 예외 연결을 방문자가 이해할 수 있는 발생 조건과 대응 문장으로 묶은 설명이다.
- **지표 해석 범위**: 측정·보고·추정 근거에 따라 결과가 의미하는 범위를 설명하는 선택 정보다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자는 두 스윔레인 각각에서 핵심 여섯 단계를 시작부터 완료까지 순서대로 식별할 수 있다.
- **SC-002**: 두 스윔레인의 정상 단계 100%가 방향성 연결로 이어지고 시작부터 완료까지 단절된 구간이 0개다.
- **SC-003**: 방문자는 설계·개발·검증의 예외 상황 3개와 CI/CD·시크릿·배포의 예외 상황 2개에서 발생 조건, 중단 범위와 다음 행동을 설명할 수 있다.
- **SC-004**: 공개 상세 화면에서 `연결과 분기`, `순서형 대체 설명`, `이전 단계로 복구`, `계속`, `제한:` 문구가 0개다.
- **SC-005**: 보충 설명이 있는 지표 100%가 근거 종류에 맞는 산정·측정·관찰 범위 문구를 제공한다.
- **SC-006**: 시각 다이어그램을 사용하지 않는 방문자가 전체 흐름 설명과 예외 대응만으로 두 흐름의 정상 순서와 대응 결과를 동일하게 파악할 수 있다.
- **SC-007**: 320px, 768px, 1024px와 1440px 화면에서 페이지 전체 가로 넘침이 1px 이하이며 필요한 가로 이동은 다이어그램 내부에 한정된다.
- **SC-008**: 키보드 사용자가 각 다이어그램 영역에 한 번의 정지로 접근해 좌우로 탐색할 수 있고 정적 단계와 연결선의 추가 정지점은 0개다.
- **SC-009**: 밝은 화면과 어두운 화면 모두에서 정상 진행과 예외 경로를 색상 이외의 수단으로 구분할 수 있다.
- **SC-010**: 변경 후에도 전체 8개 작업물 공개 경로에 접근할 수 있고 하네스 외 7개 작업물의 기존 본문 손실이 0건이다.
- **SC-011**: 잘못된 흐름 데이터에 정의된 모든 게시 차단 조건이 자동 검증에서 100% 탐지된다.
- **SC-012**: 정의된 콘텐츠 계약, 렌더링, 접근성, 반응형, 전체 페이지 생성과 공개 경로 검증이 통과한 상태에서만 기능 완료로 판정된다.

## Assumptions

- 두 스윔레인은 실행 가능한 데모가 아니라 하네스의 책임과 운영 흐름을 설명하는 정적 증거다.
- 세부 내부 단계보다 승인된 핵심 여섯 단계와 중요한 중단·복귀 경로를 우선한다.
- 정상 흐름은 위에서 아래로 읽고 책임 이동은 세로 영역 사이를 가로지르는 연결로 표현한다.
- 보충 설명이 없는 지표에는 산정·측정·관찰 범위 label을 표시하지 않는다.
- 다이어그램 노드는 상호작용 요소가 아니며 탐색 가능한 링크나 버튼을 포함하지 않는다.
- 하네스 작업물의 공개 사실, 지표 값, 현재·역사 도구와 네 인사이트 범위는 이번 변경에서 수정하지 않는다.
- 하네스 외 작업물은 각자의 인터뷰가 완료될 때까지 기존 상세 표시 방식을 유지한다.
- 자동 상태 동기화 작업이 계속 제공되지 않으면 검증 기록과 `ROADMAP.md`에서 상태를 수동 관리한다.
