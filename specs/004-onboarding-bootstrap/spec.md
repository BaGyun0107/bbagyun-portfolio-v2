# Feature Specification: 하네스 원클릭 온보딩 부트스트랩 (Phase 1)

**Feature Branch**: `004-onboarding-bootstrap`

**Created**: 2026-07-15

**Status**: Draft

**Input**: User description: "macOS 전용 멱등 부트스트랩 커맨드가 도구 설치부터
하네스 설치·검증까지 한 번에 수행한다. 설계 문서
설계 초안(2026-07-18 정리 — git history) 참조."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 신규 팀원 원클릭 온보딩 (Priority: P1)

개발 도구가 전혀 없는 새 macOS 머신을 받은 팀원이, 레포를 clone한 뒤 커맨드
하나를 실행하면 하네스 작업에 필요한 모든 도구가 준비된 상태가 된다. 도구
이름(mise, bun, uv 등)을 몰라도 화면의 안내만 따라가면 완료된다.

**Why this priority**: 이 기능의 존재 이유. 현재 온보딩은 mise·bun·uv·
Superpowers를 각각 수동 설치해야 하며, 도구에 익숙하지 않은 팀원이 막히는
지점이다.

**Independent Test**: 도구가 없는 macOS 환경(또는 이를 흉내 낸 격리 환경)에서
커맨드 1회 실행 후 doctor 검증이 통과하면 성공.

**Acceptance Scenarios**:

1. **Given** git 외 개발 도구가 없는 macOS 머신, **When** 부트스트랩 커맨드를
   실행하면, **Then** 런타임 관리자와 필수 도구가 모두 설치되고 하네스 설치와
   검증까지 완료되었다는 요약이 표시된다.
2. **Given** GitHub 미인증 상태, **When** 부트스트랩이 인증 단계에 도달하면,
   **Then** 대화형 로그인 안내가 나오고 완료 후 나머지 단계가 이어진다.
3. **Given** 부트스트랩이 정상 완료된 머신, **When** 하네스 기능(스킬·훅)을
   사용하는 세션을 시작하면, **Then** 도구 누락 에러가 발생하지 않는다.

### User Story 2 - 재실행해도 안전한 멱등 실행 (Priority: P2)

이미 일부(또는 전부) 도구가 설치된 팀원이 부트스트랩을 다시 실행해도 아무것도
망가지지 않는다. 이미 충족된 단계는 "확인됨"으로 건너뛰고, 빠진 것만 채운다.
설치가 중간에 실패했던 경우에도 재실행만 하면 이어서 진행된다.

**Why this priority**: 부분 실패 복구와 기존 사용자 재실행이 안전해야
"막히면 다시 실행하세요"라는 단일 안내가 성립한다.

**Independent Test**: 정상 완료된 머신에서 재실행 → 변경 0건으로 빠르게 종료.
중간 단계 실패를 흉내 낸 뒤 재실행 → 남은 단계만 수행되고 완료.

**Acceptance Scenarios**:

1. **Given** 부트스트랩이 이미 완료된 머신, **When** 다시 실행하면, **Then**
   모든 단계가 확인·스킵되고 기존 설정(셸 프로필 등)에 중복 항목이 생기지
   않는다.
2. **Given** 도구 설치 단계에서 중단된 머신, **When** 재실행하면, **Then**
   완료된 단계는 건너뛰고 남은 단계부터 이어서 완료된다.

### User Story 3 - Superpowers 플러그인 자동 준비 (Priority: P3)

부트스트랩이 Superpowers 플러그인의 자동 설치를 시도한다. 자동 설치가
불가능한 환경이면, 사용자가 그대로 따라 하면 되는 설치 안내를 마지막 요약에
표시한다.

**Why this priority**: 현재 유일하게 세션 안 수동 단계로 남는 항목. 자동화가
안 되더라도 안내 폴백으로 온보딩 흐름 자체는 완결된다.

**Independent Test**: 플러그인 미설치 상태에서 부트스트랩 실행 → 자동 설치
성공 또는 명확한 수동 안내 중 하나가 반드시 제공된다.

**Acceptance Scenarios**:

1. **Given** Superpowers 미설치 상태, **When** 부트스트랩이 완료되면, **Then**
   플러그인이 설치되어 있거나, 설치를 완료할 수 있는 단계별 안내가 요약에
   포함된다.
2. **Given** Superpowers가 이미 설치된 상태, **When** 부트스트랩을 실행하면,
   **Then** 중복 설치 시도 없이 "확인됨"으로 넘어간다.

### Edge Cases

- 미지원 OS(Linux/Windows)에서 실행: 즉시 명확한 미지원 에러와 함께 종료하며,
  아무 변경도 만들지 않는다.
- 네트워크 불가: 어느 단계에서든 다운로드 실패 시 원인(네트워크)과 "연결 후
  재실행" 안내를 표시하고, 그때까지의 완료 상태는 보존된다.
- Xcode Command Line Tools 미설치: 시스템 설치 창은 부트스트랩이 대신 완료할
  수 없으므로, 설치 창을 띄운 뒤 "설치 완료 후 재실행" 안내로 종료한다.
- 동일 도구가 다른 방식(예: 수동 설치)으로 이미 존재: 기존 설치를 망가뜨리지
  않고, 하네스 작업에 필요한 버전이 사용 가능함만 보장한다.
- 셸 프로필에 활성화 설정이 이미 존재: 중복 추가하지 않는다.
- GitHub 인증을 사용자가 건너뜀/실패: 인증이 필요한 이후 단계는 수행할 수
  없음을 알리고, 재실행 시 인증 단계부터 이어진다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 레포 clone 직후 단일 커맨드로 온보딩 전체(도구 준비 →
  하네스 설치 → 검증)를 수행할 수 있어야 한다.
- **FR-002**: 부트스트랩은 macOS에서만 동작하며, 그 외 OS에서는 변경 없이
  명확한 미지원 에러로 종료해야 한다.
- **FR-003**: 부트스트랩은 멱등이어야 한다 — 재실행 시 이미 충족된 단계는
  건너뛰고, 어떤 중복 설정(셸 프로필 등)도 만들지 않는다.
- **FR-004**: 필요한 도구 목록과 버전은 레포에 커밋된 도구 버전 정의가
  소유해야 하며, 부트스트랩 자체에 도구 목록을 하드코딩하지 않는다. 도구가
  추가되어도 부트스트랩 수정 없이 반영되어야 한다.
- **FR-005**: 부트스트랩은 git과 개발자 기본 도구의 존재를 확인하고, 없으면
  설치를 유도해야 한다.
- **FR-006**: 부트스트랩은 런타임 관리자를 자동 설치하고 셸에서 즉시 사용
  가능하도록 활성화 설정을 구성해야 한다.
- **FR-007**: 부트스트랩은 도구 버전 정의에 선언된 모든 도구(현재: node,
  bun, uv, pnpm, gh)를 자동 설치해야 한다.
- **FR-008**: 부트스트랩은 GitHub 인증 상태를 확인하고, 미인증이면 대화형
  로그인 절차를 안내한 뒤 이어서 진행해야 한다.
- **FR-009**: 도구 준비가 끝나면 기존 하네스 설치 흐름(`./harness install`)에
  위임하여 하네스 구성(스킬 링크, GStack, Spec Kit 자산)을 완료해야 한다.
- **FR-010**: 부트스트랩은 Superpowers 플러그인 자동 설치를 시도하고, 자동
  설치가 불가능하면 수동 설치 안내를 최종 요약에 포함해야 한다. (검증 V1:
  자동 설치 실측 결과에 따라 시도 방식 확정)
- **FR-011**: 부트스트랩 종료 시 설치 상태 검증(doctor)을 실행하고, 단계별
  성공/스킵/실패와 남은 수동 단계를 한국어 요약으로 표시해야 한다.
- **FR-012**: 각 단계는 실패 시 원인과 "다음에 할 행동"을 함께 표시해야 하며,
  실패 후 재실행하면 실패 지점부터 이어져야 한다.
- **FR-013**: 부트스트랩과 그 구현 작업은 기존 가드레일 정책과 충돌하지
  않아야 한다. 특히 앱 패키지 매니저 정책(bun 차단)은 도구 설치 경로에는
  적용되지 않도록 정책 예외를 함께 정의한다. (검증 V3)

### Key Entities

- **도구 버전 정의**: 하네스 작업에 필요한 도구와 버전의 단일 출처. 레포에
  커밋되어 CI와 부트스트랩이 함께 읽는다.
- **설치 상태**: 각 단계의 충족 여부. 부트스트랩은 실행 시점마다 실제 환경을
  검사해 파생하며, 별도 상태 파일에 의존하지 않는다(멱등성의 근거).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 개발 도구가 없는 새 macOS 머신에서, 사용자의 대화형 입력이
  필요한 지점이 2회(시스템 개발자 도구 설치 창, GitHub 로그인) 이하로 온보딩이
  완료된다.
- **SC-002**: 정상 네트워크 기준, 신규 머신 온보딩이 15분 이내에 끝난다.
- **SC-003**: 이미 완료된 머신에서 재실행은 1분 이내에 변경 0건으로 끝난다.
- **SC-004**: 부트스트랩 완료 직후 설치 검증(doctor)이 도구 누락 없이
  통과한다.
- **SC-005**: 도구 수동 설치 안내 문서 없이, 신규 팀원이 화면 안내만으로
  온보딩을 완료할 수 있다(첫 시도 완주율 100%를 목표로 팀 내 실사용 확인).

## Assumptions

- 사용자는 회사 GitHub 조직에 대한 접근 권한(초대 완료)을 이미 갖고 있다.
- 대상 머신은 macOS이며 Apple Silicon/Intel 모두 지원한다.
- claude/codex CLI 자체의 설치와 로그인, tmux/cmux는 이번 범위 밖이다
  (필요 시 요약에 안내만 표시).
- 부트스트랩 실행에는 인터넷 연결이 필요하다(오프라인 설치는 범위 밖).
- 이번 Phase 1은 현행 복사+동기화 구조 위에 얹는다. 패키지화(글로벌 캐시,
  버전 lock)는 Phase 2의 별도 spec으로 다룬다. 상위 설계:
  설계 초안(2026-07-18 정리 — git history)
- Superpowers 자동 설치 가능 여부(V1)는 plan 단계에서 실측으로 확정하며,
  결과와 무관하게 안내 폴백으로 사용자 흐름은 완결된다.
