# Feature Specification: 반응형 스윔레인 뷰어

**Feature Branch**: `chore/cleanup-downstream-harness`

**Created**: 2026-09-01

**Updated**: 2026-09-01 — 실제 화면에서 발견한 node 글자 축소와 edge label 충돌을
구조 보존형 반응형 geometry로 보완하는 후속 범위를 추가함

**Status**: Draft

**Input**: User description: "작업물 상세의 스윔레인에서 가로 스크롤을 제거하고 크게 보기 기능을 제공한다. 연결선은 FigJam처럼 자연스러운 둥근 경로로 표현하되 상·하·좌·우 어느 방향에서도 곡선과 작은 화살촉이 깨져 보이지 않아야 한다. 라벨은 읽기 좋은 위치에 표시하고 도착점에는 포트나 굵은 점을 만들지 않는다. 후속으로 현재 lane·node·edge 구조는 유지하면서 축소된 글자를 읽을 수 있게 하고, edge 라벨은 각 경로 중앙을 기본으로 충돌할 때만 위·아래로 최소 조정한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스크롤 없이 전체 흐름 파악 (Priority: P1)

작업물 상세를 읽는 방문자는 스윔레인 때문에 본문을 좌우로 이동하지 않고 카드 안에서
전체 책임 주체와 흐름의 방향을 먼저 파악하고 싶다.

**Why this priority**: 스윔레인은 프로젝트 판단을 설명하는 핵심 증거이며, 가로 스크롤은
본문의 읽기 흐름을 끊고 다이어그램 전체 구조를 비교하기 어렵게 만든다.

**Independent Test**: 지원하는 가장 좁은 화면부터 데스크톱까지 작업물 상세를 열고,
스윔레인 카드와 페이지에 가로 스크롤이 생기지 않으면서 모든 lane과 전체 흐름이 카드
안에 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 방문자가 스윔레인이 있는 작업물 상세를 열었을 때, **When** 시스템 흐름 영역에 도달하면, **Then** 다이어그램 전체가 카드 너비 안에 표시되고 가로 스크롤바가 나타나지 않는다.
2. **Given** 방문자가 작은 화면을 사용할 때, **When** 본문 다이어그램을 확인하면, **Then** 페이지 폭이 늘어나지 않고 전체 구조와 진행 방향을 미리보기로 파악할 수 있다.
3. **Given** 하나의 상세에 여러 스윔레인이 있을 때, **When** 각 카드를 순서대로 읽으면, **Then** 모든 카드가 동일한 반응형 규칙을 사용한다.

---

### User Story 2 - 자연스러운 연결선 추적 (Priority: P1)

방문자는 각 단계의 연결선이 어느 노드에서 출발해 어느 노드의 어느 변에 도착하는지
화살촉과 곡선의 깨짐 없이 자연스럽게 추적하고 싶다.

**Why this priority**: 연결선과 화살촉이 모서리에서 겹치거나 크기 비례가 맞지 않으면
흐름의 의미보다 렌더링 결함이 먼저 보이고 포트폴리오 완성도가 낮아진다.

**Independent Test**: 상·하·좌·우 네 방향으로 도착하는 대표 흐름에서 곡선과 화살촉이
하나의 방향으로 이어지고, 도착점에 별도의 점이나 포트가 없으며, 라벨이 잘리지 않는지
확인한다.

**Acceptance Scenarios**:

1. **Given** source와 target이 가로로 떨어져 있을 때, **When** 연결선을 따라가면, **Then** 가까운 좌우 변을 사용하는 짧고 자연스러운 경로를 우선한다.
2. **Given** source와 target이 세로로 떨어져 있을 때, **When** 연결선을 따라가면, **Then** 가까운 상하 변을 사용하는 경로를 우선한다.
3. **Given** 연결선이 어느 변에 도착하든, **When** 곡선과 화살촉을 확대해 확인하면, **Then** 마지막 직선과 화살촉이 같은 방향으로 이어지고 화살촉의 끝이 노드 변에 정확히 닿는다.
4. **Given** 정상 흐름과 예외 흐름이 함께 있을 때, **When** 연결선을 비교하면, **Then** 색상 외에도 실선과 점선으로 구분할 수 있다.
5. **Given** 연결선에 라벨이 있을 때, **When** 다이어그램을 확인하면, **Then** 라벨은 선과 분리된 읽기 쉬운 영역에 표시되고 다이어그램 경계에서 잘리지 않는다.

### User Story 3 - 동일한 흐름을 크게 확인 (Priority: P2)

방문자는 본문 미리보기에서 구조를 파악한 뒤 필요할 때 같은 다이어그램을 더 넓은
화면에서 자세히 보고 싶다.

**Why this priority**: 본문 가로 스크롤을 없애면 복잡한 흐름의 글자가 작아질 수 있으므로
세부 내용을 읽을 수 있는 명시적인 확대 경로가 필요하다.

**Independent Test**: 스윔레인 카드의 `크게 보기`를 실행해 같은 lane, node, edge와
라벨이 대형 보기 안에 표시되는지 확인하고 키보드로 닫은 뒤 실행 버튼으로 포커스가
돌아오는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 방문자가 스윔레인 카드를 보고 있을 때, **When** `크게 보기`를 실행하면, **Then** 동일한 다이어그램이 화면 대부분을 사용하는 대형 보기에 열린다.
2. **Given** 대형 보기가 열려 있을 때, **When** 방문자가 본문 미리보기와 비교하면, **Then** lane, node, edge, 라벨과 예외 구분이 동일하다.
3. **Given** 키보드 사용자가 대형 보기를 열었을 때, **When** Escape로 닫으면, **Then** 포커스가 해당 스윔레인의 `크게 보기` 버튼으로 돌아온다.
4. **Given** 터치 장치를 사용하는 방문자가 있을 때, **When** 다이어그램을 확인하면, **Then** 마우스 올림 동작 없이 명시적인 버튼으로 대형 보기를 열 수 있다.

---

### User Story 4 - 시각화 없이도 같은 의미 이해 (Priority: P2)

키보드와 보조 기술을 사용하는 방문자는 다이어그램이 축소되거나 시각 연결선을 직접
해석하지 못해도 동일한 전체 흐름과 예외 대응을 이해하고 싶다.

**Why this priority**: 다이어그램은 장식이 아니라 작업물의 시스템 판단을 전달하는
콘텐츠이므로 화면 크기나 시각 정보 접근 여부와 관계없이 의미가 보존돼야 한다.

**Independent Test**: 다이어그램을 보지 않고 접근 가능한 이름, 전체 흐름 설명과 예외
대응을 읽어 시각 다이어그램과 같은 흐름을 설명할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 보조 기술 사용자가 스윔레인에 도달했을 때, **When** 다이어그램을 탐색하면, **Then** 고유한 이름과 전체 흐름 설명을 제공받는다.
2. **Given** 한 페이지에 본문·대형 보기와 여러 스윔레인이 존재할 때, **When** 접근 가능한 이름을 조회하면, **Then** 각 다이어그램을 서로 구분할 수 있다.
3. **Given** 키보드 사용자가 상세를 탐색할 때, **When** 정적인 node와 edge를 지나가면, **Then** 불필요한 키보드 정지점이 추가되지 않는다.

---

### User Story 5 - 구조를 유지하면서 모든 글자를 읽는다 (Priority: P1)

방문자는 작은 화면에서도 기존 스윔레인의 lane, node와 연결 관계를 그대로 보면서
node 문구와 분기 조건을 서로 겹치지 않는 크기로 읽고 싶다.

**Why this priority**: 가로 스크롤이 없더라도 전체 다이어그램을 통째로 축소해 글자가
3~10px 수준으로 작아지거나 label끼리 겹치면 흐름의 근거를 실제로 읽을 수 없다.

**Independent Test**: 지원하는 모든 화면 폭에서 구조화 작업물 4개·스윔레인 6개의
본문과 대형 보기를 열어 node 글자 크기, node 내부 줄바꿈, edge label 기본 위치와
라벨끼리의 충돌 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 방문자가 4-lane 스윔레인을 작은 화면에서 볼 때, **When** node 문구를 읽으면, **Then** lane 수와 node 관계는 유지되고 글자는 실제 표시 크기 10px 이상이다.
2. **Given** lane 폭보다 긴 node 문구가 있을 때, **When** 다이어그램이 좁아지면, **Then** 문구는 node 안에서 여러 줄로 표시되고 node와 row 높이가 함께 늘어난다.
3. **Given** 서로 다른 길이의 edge에 label이 있을 때, **When** 자동 위치를 계산하면, **Then** 각 label은 자기 경로 전체 길이의 중앙을 기본 위치로 사용한다.
4. **Given** 중앙에 둔 label끼리 겹칠 때, **When** 충돌을 해소하면, **Then** 겹치는 label만 중앙에서 가장 가까운 위·아래 위치로 이동하고 한 줄 표기를 우선한다.
5. **Given** 위·아래 이동만으로 공간이 부족할 때, **When** label을 배치하면, **Then** 전체 문구를 유지한 채 필요한 label만 여러 줄로 표시한다.
6. **Given** 명시적인 label 위치가 있을 때, **When** 자동 label을 함께 배치하면, **Then** 명시 위치는 움직이지 않고 자동 label이 이를 피한다.
7. **Given** 서로 다른 행과 lane의 node를 잇는 연결선이 있을 때, **When** 경로를 계산하면, **Then** 출발·도착 사이에 실제로 놓인 장애물만 우회하고 연결 대상이 아닌 node나 그 문구를 관통하지 않는다.
8. **Given** 하나의 판단 node가 같은 다음 행의 여러 결과 node로 분기할 때, **When** 경로를 계산하면, **Then** 같은 lane의 결과는 수직으로 직접 연결하고 좌우 결과는 목적지의 왼쪽→오른쪽 순서에 맞는 서로 다른 높이의 통로를 사용한다.
9. **Given** 같은 행의 source에서 target의 위·아래 변으로 연결할 때, **When** 경로를 계산하면, **Then** target 내부나 문구를 먼저 가로지르지 않고 target 바깥 통로를 지난 뒤 지정된 변으로 진입한다.

### Edge Cases

- lane이 하나뿐이거나 lane 수가 많아도 본문 카드와 페이지에 가로 넘침을 만들지 않는다.
- 한 상세에서 여러 스윔레인을 렌더링하고 같은 흐름의 본문·대형 보기가 동시에 존재해도 접근 가능한 이름과 도형 식별자가 충돌하지 않는다.
- source 또는 target의 상대 위치가 대각선에 가까우면 더 짧고 장애물이 적은 방향을 선택한다.
- 명시된 출발·도착 방향과 경유 지점이 있으면 자동 선택보다 우선하되 모서리를 도착점으로 사용하지 않는다.
- 연결 구간이 짧으면 곡선 크기를 줄여 노드 내부로 침범하거나 화살촉과 겹치지 않게 한다.
- 라벨이 없으면 빈 라벨 배경을 만들지 않는다.
- 긴 한글 라벨은 중앙 위치의 한 줄 표기를 우선하되, 위·아래 조정으로도 공간을
  확보할 수 없을 때만 전체 문구를 여러 줄로 표시한다.
- 자동 라벨의 중앙 위치에 충분한 공간이 없으면 다른 label과 node를 피하는 가장 가까운
  위·아래 위치를 사용하고, 명시된 label 위치는 자동으로 이동하지 않는다.
- 예외 흐름이 없으면 예외 표현이나 빈 예외 영역을 만들지 않는다.
- 작은 화면에서 lane 폭이 좁아지면 스윔레인의 가로 구조를 바꾸지 않고 node와 row의
  세로 길이를 늘려 실제 글자 크기를 유지한다.
- node 문구가 여러 줄이 되면 decision을 포함한 모든 node 도형 안에서 문구가 잘리지
  않아야 한다.
- 자동 label을 세 줄까지 표시해도 충돌을 피할 수 없으면 문구를 숨기거나 겹쳐 그리지
  않고 게시 전 검증에서 차단한다.
- 잘못된 node·edge 참조나 유효하지 않은 위치는 임의로 그리지 않고 게시 전 검증에서 차단한다.
- 같은 가로 범위에 있지만 출발·도착의 세로 구간 밖에 있는 node는 우회 장애물로 오인하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 모든 구조화 작업물의 본문 스윔레인은 지원 화면 너비에서 카드와 페이지에 가로 스크롤을 만들지 않아야 한다.
- **FR-002**: 본문 스윔레인은 lane과 흐름 전체를 카드 너비 안에 맞춘 미리보기로 제공해야 한다.
- **FR-003**: 각 스윔레인 카드는 보이는 `크게 보기` 버튼을 제공해야 한다.
- **FR-004**: 대형 보기는 본문과 동일한 스윔레인 데이터와 표현 규칙을 사용해야 한다.
- **FR-005**: 대형 보기는 데스크톱과 모바일의 가용 화면 안에서 다이어그램 전체를 제공하고 별도의 가로 스크롤을 만들지 않아야 한다.
- **FR-006**: 대형 보기는 click, touch와 keyboard로 열 수 있어야 하며 hover만으로 열리지 않아야 한다.
- **FR-007**: 대형 보기는 Escape로 닫을 수 있고 닫은 뒤 포커스를 실행한 버튼으로 돌려야 한다.
- **FR-008**: 출발·도착 방향이 명시되지 않은 연결은 source와 target의 상대 위치를 기준으로 자연스러운 상·하·좌·우 변을 선택해야 한다.
- **FR-009**: 명시된 출발·도착 방향, 경유 지점과 라벨 위치는 자동 계산보다 우선하는 override로 유지해야 한다.
- **FR-010**: 모든 anchor는 노드 모서리가 아닌 상·하·좌·우 변 위에서 계산돼야 한다.
- **FR-011**: 연결선은 둥근 직교 경로와 그 마지막 방향을 따르는 단일 화살촉으로 표현돼야 한다.
- **FR-012**: 연결선은 2px 굵기, 6px 화살촉과 8px 기본 곡률의 승인된 비례를 유지해야 한다.
- **FR-013**: 화살촉에 도착하기 전 연결선은 최소 10px의 직선 구간을 확보하고 target 변에 수직으로 진입해야 한다.
- **FR-014**: 연결선 도착점에는 수신 포트, 굵은 점 또는 halo를 표시하지 않아야 한다.
- **FR-015**: 연결선 끝의 둥근 뭉침이 화살촉 아래에 겹쳐 보이지 않아야 한다.
- **FR-016**: 정상과 예외 흐름은 색상 이외에 실선과 점선으로 구분돼야 한다.
- **FR-017**: 연결선 라벨은 뒤의 선과 분리된 pill로 제공하고 기본적으로 각 연결 경로 전체 길이의 중앙에 배치해야 한다.
- **FR-018**: 라벨 pill은 전체 문자열을 표시하고 다이어그램 경계를 벗어나거나 잘리지 않아야 한다.
- **FR-019**: 본문과 대형 보기의 각 다이어그램은 서로 충돌하지 않는 고유한 접근 가능한 이름과 내부 식별자를 가져야 한다.
- **FR-020**: 정적인 node와 edge는 개별 키보드 정지점을 만들지 않아야 한다.
- **FR-021**: 각 스윔레인은 시각 흐름과 동일한 전체 흐름 설명과 예외 대응 문장을 계속 제공해야 한다.
- **FR-022**: 기존 구조화 작업물의 스윔레인 내용, 순서, 공개 문구와 의미는 변경하지 않아야 한다.
- **FR-023**: 잘못된 참조, 위치, 경로 또는 필수 설명은 게시 가능한 다이어그램으로 취급하지 않아야 한다.
- **FR-024**: 다이어그램의 배치·표현·상호작용 변경은 정의된 검증을 모두 통과해야 게시 가능한 상태로 간주해야 한다.
- **FR-025**: 지원 화면 폭에 맞춰 node와 lane의 표시 크기가 달라져도 기존 lane 열, node 소속, edge 관계와 진행 순서는 유지돼야 한다.
- **FR-026**: 본문과 대형 보기의 node 글자는 지원 화면 폭에서 실제 표시 크기 10px 이상이어야 한다.
- **FR-027**: node 문구가 가용 폭보다 길면 전체 문구를 node 안에서 여러 줄로 표시하고, node 높이와 row 간격은 문구를 수용하도록 늘어나야 한다.
- **FR-028**: 자동 edge label이 중앙에서 다른 label, node 또는 다이어그램 경계와 충돌하면 해당 label만 중앙에서 가장 가까운 위·아래 유효 위치로 이동해야 한다.
- **FR-029**: 명시적인 label 위치는 자동 이동하지 않아야 하며 자동 label은 명시 label을 피해야 한다.
- **FR-030**: edge label은 한 줄을 우선하고, 위·아래 이동으로도 충돌을 피할 수 없을 때만 전체 문구를 두 줄, 이후 세 줄로 표시해야 한다.
- **FR-031**: 세 줄 표시까지 적용해도 label 충돌을 피할 수 없는 다이어그램은 문구를 숨기거나 겹쳐 표시하지 않고 게시 가능한 상태로 취급하지 않아야 한다.
- **FR-032**: 연결선은 source와 target이 아닌 node의 도형·문구 안전 영역을 통과하지 않아야 하며, 출발·도착 세로 구간 밖의 node 때문에 불필요하게 반대 방향으로 우회하지 않아야 한다.
- **FR-033**: 하나의 source가 같은 target 행의 세 개 이상 node로 상·하 분기하면, 같은 lane의 직접 경로는 꺾지 않고 서로 다른 lane으로 향하는 경로는 target의 좌→우 순서에 따라 결정적인 별도 수평 통로를 사용해야 한다.
- **FR-034**: 같은 행의 가로 anchor에서 출발해 target의 세로 anchor로 도착하는 연결선은 마지막 도착 구간 전에 target 도형·문구 영역을 통과하지 않아야 한다.

### Key Entities

- **스윔레인 뷰어**: 제목, 목적, 본문 미리보기, 대형 보기 버튼, 전체 흐름 설명과 예외 대응을 묶어 제공하는 읽기 단위다.
- **스윔레인 다이어그램**: lane, node, edge와 label로 구성되며 본문과 대형 보기에서 동일한 의미를 유지하는 시각 증거다.
- **연결 경로**: source와 target, 선택 또는 명시된 출발·도착 방향, 선택적 경유 지점, 정상·예외 구분과 라벨을 가진 방향성 관계다.
- **Anchor**: 연결선이 노드의 상·하·좌·우 변에서 출발하거나 도착하는 위치다. 명시되지 않으면 노드 상대 위치로 선택된다.
- **라벨 배치**: 연결선의 의미를 보여주는 문자열, rounded path 전체 길이의 50% 지점
  또는 명시 위치, pill 크기와 충돌 회피 정보를 가진다.
- **반응형 배치**: 같은 lane·node·edge 관계를 유지하면서 화면 폭에 맞춰 node 크기,
  문구 줄 수와 row 간격을 조정한 표시 상태다.
- **보기 인스턴스**: 동일한 스윔레인이 본문과 대형 보기에 함께 존재할 때 접근 가능한 이름과 내부 식별자를 구분하는 표시 단위다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 320px, 375px, 768px, 1024px와 1440px 화면에서 스윔레인 카드와 상세 페이지의 가로 넘침이 0px이다.
- **SC-002**: 구조화 상세를 사용하는 모든 작업물의 모든 스윔레인이 본문 미리보기와 대형 보기에서 같은 lane, node, edge, label과 예외 구분을 제공한다.
- **SC-003**: 상·하·좌·우 도착 검증 사례 100%에서 마지막 직선과 화살촉이 같은 방향으로 이어지고 도착점의 포트·점·강조 테두리가 0개다.
- **SC-004**: 기존 스윔레인의 라벨 100%가 본문과 대형 보기에서 전체 문자열을 표시하며 잘린 라벨이 0개다.
- **SC-005**: 키보드 사용자는 한 번의 버튼 실행으로 대형 보기를 열고 Escape로 닫은 뒤 원래 버튼으로 포커스를 돌려받는다.
- **SC-006**: 같은 페이지에 존재하는 모든 본문·대형 보기 다이어그램의 접근 가능한 이름과 내부 식별자 충돌이 0건이다.
- **SC-007**: 정적 node와 edge가 추가하는 키보드 정지점은 0개다.
- **SC-008**: 정상·예외 흐름 100%가 색상 외에도 실선·점선으로 구분된다.
- **SC-009**: Blackstone, Hanmaum, Harness와 중앙 회원 서버의 기존 스윔레인 내용·순서·문구 손실이 0건이다.
- **SC-010**: 정의된 단위·렌더링·접근성·반응형·브라우저 검증이 모두 통과한 상태에서만 기능 완료로 판정된다.
- **SC-011**: 320px, 375px, 768px, 1024px와 1440px 화면의 모든 본문·대형 보기에서 node 글자의 실제 표시 크기가 10px 이상이다.
- **SC-012**: 구조화 작업물 4개·스윔레인 6개의 모든 본문·대형 보기에서 node 문구가 node 경계를 벗어나는 사례가 0건이다.
- **SC-013**: 모든 자동 edge label의 기본 중심이 해당 경로 전체 길이의 50% 지점이며, 충돌이 없는 label의 추가 이동은 0px이다.
- **SC-014**: 구조화 작업물 4개·스윔레인 6개의 모든 본문·대형 보기에서 label-label, label-node와 label-boundary 충돌이 각각 0건이다.
- **SC-015**: 반응형 배치 전후 lane 수, node 수, edge 수, 소속 관계, 순서와 공개 문구 손실이 0건이다.
- **SC-016**: 구조화 작업물 4개·스윔레인 6개의 모든 지원 폭에서 연결선과 비연결 node의 교차가 0건이고, 아래쪽 흐름이 세로 범위 밖의 위쪽 node 때문에 역방향으로 우회하는 사례가 0건이다.
- **SC-017**: Blackstone 결제 결과의 세 cross-lane 분기는 252·307·684·766.7px에서 서로 다른 수평 통로를 사용하고 그 높이가 목적지 좌→우 순서와 100% 일치하며, PMS 장애의 same-lane 분기는 수직 직선으로 유지된다.
- **SC-018**: Harness의 `시크릿 불일치 → 배포 중단` 경로는 지원 폭 100%에서 node 내부 교차가 0건이고 아래쪽 변으로 수직 진입한다.

## Assumptions

- 주요 사용자는 작업물 상세에서 기술적 판단과 시스템 흐름을 확인하는 방문자다.
- 본문 다이어그램은 전체 구조를 파악하는 미리보기이지만 node 문구와 edge label도
  지원 화면 폭에서 직접 읽을 수 있어야 한다. 대형 보기와 텍스트 설명은 추가 읽기
  경로이지, 읽을 수 없는 본문을 대신하는 수단으로 사용하지 않는다.
- 대형 보기는 확대율을 저장하거나 자유롭게 편집하는 캔버스가 아니라 같은 정적 다이어그램을 더 넓게 읽는 수단이다.
- 현재 데이터에 있는 출발·도착 방향, 경유 지점과 라벨 위치는 유효한 명시적 override로 간주한다.
- 신규 연결은 출발·도착 방향을 생략할 수 있고 이 경우 상대 위치 기반 기본 방향을 사용한다.
- 기존 전체 흐름 설명과 예외 대응이 시각 다이어그램의 텍스트 대안으로 유지된다.
- 승인된 시각 기준의 상세 근거는 `docs/superpowers/specs/2026-09-01-responsive-swimlane-viewer-design.md`에 기록돼 있다.
- 2026-09-01 가독성 후속 측정과 승인 규칙은 `docs/superpowers/specs/2026-09-01-responsive-swimlane-readability-followup-design.md`에 기록돼 있다.
- 구현과 검증은 현재 애플리케이션 환경과 공통 작업물 상세 구조를 유지한다.
