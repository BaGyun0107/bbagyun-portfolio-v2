# Phase 0 Research: 블랙스톤 벨포레 리조트 구조화 상세 이전

**Date**: 2026-08-24

Technical Context에 `NEEDS CLARIFICATION` 항목은 없다. 인터뷰와 인계 문서에서
역할, 사실 정정, 지표 근거, 스윔레인 개수가 확정되었고 재사용할 계약과 연결
인사이트는 저장소에서 직접 확인했다. 아래는 구현 전에 확정한 결정과 근거다.

## D-001. 신규 렌더러나 타입을 만들지 않고 기존 계약을 재사용한다

**Decision**: `FeatureDetailDto`, `ProjectDetailContent`, `ProjectHighlights`,
`ProjectSwimlane` 계열 렌더러와 `validateFeatureDetail`을 그대로 사용한다.

**Rationale**: 블랙스톤 이전은 새 표현 방식이 아니라 세 번째 구조화 데이터
구현이다. 기존 두 작업물이 이미 공통 10섹션, 근거 지표, 선택적 스윔레인,
연결 인사이트를 같은 계약으로 제공한다.

**Alternatives considered**:

- 블랙스톤 전용 렌더러: 기각. 작업물 비교 가능성이 사라지고 회귀 범위가 넓어진다.
- 공통 렌더러 리팩터링: 기각. 현재 계약으로 요구사항을 모두 표현할 수 있어
  별도 구조 변경의 이익이 없다.

## D-002. 결과 지표 두 개만 근거 등급과 함께 남긴다

**Decision**:

| 지표 | 값 | kind | asOf | 근거·한계 |
| --- | --- | --- | --- | --- |
| 컴플레인 접수 불일치 | 10건 미만 | `reported` | `2026-08` | 고객 컴플레인 접수 기준. 시스템 집계가 아니며 실제 불일치의 하한 |
| 운영 관찰 기간 | 2024년 오픈 ~ 현재 진행 중 | `reported` | `현재 진행 중` | 유지보수 중 같은 유형 문제가 없었다는 인터뷰 회고 범위 |

**Rationale**: 핵심 결과 카드는 현재 전달 가치가 큰 컴플레인 범위와 운영 관찰
기간만 남긴다. 약 20초는 당시 API 문제로 지연된 상태이지 PMS의 정상 평균
성능이 아니며, 약 1시간의 장애 지속 시간도 결과 카드보다 장애 대응 맥락이다.

**Alternatives considered**:

- 컴플레인 10건 미만을 `measured`로 표기: 기각. 로그·DB 집계가 아니다.
- PMS 약 20초와 장애 약 1시간을 별도 카드로 유지: 기각. timeout 교훈을
  설명하는 데 필요한 최소 맥락만 본문에 남긴다.
- 평일 10건 이상·주말 30건 이상을 별도 지표로 추가: 기각. 사용자가 정확하지
  않다고 밝혔으며 성수기 편차와 총 결제 건수를 확인할 수 없다.
- 일별 추정으로 누적 건수나 비율 계산: 금지. 근거 없는 정밀도다.

## D-003. 역할은 유지하고 사실 오류 6종을 문장 단위로 정정한다

**Decision**:

1. 역할은 "모든 설계를 혼자 했고 1인 백엔드로 전반을 주도"한 수준을 유지한다.
2. `10건 미만`은 고객 컴플레인으로 접수된 불일치이며 실제 불일치의 하한으로 쓴다.
3. PHP·React 결합은 기존 그누보드 자산 위의 신규 구축으로 쓴다. 무중단 전환은
   선택 근거나 성과가 아니다.
4. timeout은 `12초 임의 설정 → 정상 처리 중 요청의 실패 오판 → 당시 API
   문제로 약 20초까지 지연 → 30초 UX와 60초 결제 안전성 사이에서 장애 대응값
   60초 선택 → 이후 API 수정` 순서로 쓴다. 약 20초를 정상 평균으로 일반화하지 않는다.
5. 2PC·이벤트 소싱 비교표를 제거한다. 실제 고민은 Node.js에서 사용하던 ORM
   트랜잭션 방식을 PHP 결제 흐름에 그대로 적용하기 어려웠던 점이다.
6. 환경변수 난독화 비교표를 제거한다. React 환경변수가 빌드 산출물에 포함되는
   사실을 몰랐다가 프로젝트 중간에 발견해 PHP 프록시로 대응한 순서를 쓴다.
7. WebView 원인은 앱 개발자에게 전달받은 내용으로 등급을 낮추고, 브릿지로
   토큰을 전달한 직접 구현 사실만 확정적으로 쓴다.

위 목록의 1은 유지 항목이고 2~7이 정정 6종이다.

**Rationale**: 잘못을 감추거나 하지 않은 대안 검토를 덧붙이는 것보다 실제
발견 순서와 판단 기준을 남기는 편이 백엔드 의사결정을 더 정확하게 보여준다.

**Alternatives considered**:

- 역할을 보수적으로 낮춤: 기각. 인터뷰에서 모든 설계를 혼자 했다고 확인됐다.
- 정정 대상 절을 통째로 삭제: 기각. 12초 임의 설정과 API Key 오해처럼 실패를
  통해 정책을 바꾼 판단이 이 작업물의 핵심 근거다.

## D-004. 연결 인사이트는 최소 범위로 사실 전제를 맞춘다

**Decision**: `spa-api-key-exposure-and-bff-architecture`를 상세와 함께 사실
일관성 검사 대상으로 둔다. 현재 인사이트의 "SPA 특성을 몰랐다가 개발자 도구에서
발견하고 PHP 프록시로 옮겼다"는 순서는 유지한다. 다만 "핫픽스"처럼 운영 중
서비스 수정으로 읽힐 수 있는 표현은 "프로젝트 중간에 확인한 즉시 수정"한
문맥으로 좁힌다. 무중단 성과나 환경변수 난독화 대안은 추가하지 않는다.

**Rationale**: feature 005에서 상세만 정정하고 직접 연결된 인사이트가 반대
사실을 주장한 Critical 회귀가 있었다. 이번에는 처음부터 두 공개 경로를 함께
검사한다. 이미 일치하는 기술 회고 전체를 다시 쓰는 것도 근거 범위를 벗어나므로
문맥 충돌만 좁게 수정한다.

**Alternatives considered**:

- 인사이트를 범위에서 제외: 기각. 독자가 상세에서 직접 따라가는 공개 경로다.
- 인사이트 전체 재작성: 기각. 현재 API Key 발견과 프록시 대응의 핵심 순서는
  인터뷰와 일치한다.

## D-005. 결제·보상취소 스윔레인 하나만 제공한다

**Decision**: 정상 결제·예약 완료 경로와 세 가지 장애 분기를 하나의
`payment-and-compensation` 스윔레인에 표현한다.

- 정상: 결제 요청 → 승인 → 결제 정보 처리 → 예약·티켓 생성 → 결과 판단 → 완료
- 예외 1: 응답 미도달·예약/티켓 실패·PHP 예외 → 서버 자동 보상취소
- 예외 2: 외부 PMS 장애 → 로그의 최초 발생 시각과 종료 시각으로 장애 구간 확인
- 예외 3: 12초 timeout 조기 실패 오판 → 60초 정책으로 보강

**Rationale**: 라우팅·인증은 단계가 단순해 그림의 추가 정보가 적다. 결제는
실패 경로가 세 갈래라 시각화 가치가 높다. 다만 `resvId`·`tid`·fallback 구현은
Q&A에서 직접 확인되지 않았으므로 공개 흐름에서 제외한다.

**검증기 제약**:

- start와 end node는 각각 정확히 하나
- 모든 stop 외 node는 start에서 normal edge로 도달하고 normal edge로 end에 도달
- normal edge는 `continue`, 더 큰 row로 진행, stop node 대상 금지
- exception edge는 `recover` 또는 `stop`, 조건 label 필수
- decision에서 나가는 모든 edge는 결과 label 필수
- `stop` outcome은 stop shape 대상
- lane·step·edge·exception ID는 스윔레인 안에서 유일하고 lane 내 row 중복 금지

## D-006. 회귀 계약을 새 상태로 원자적으로 재고정한다

**Decision**:

1. 구조화 상세 목록:
   `codi-harness-dx-platform`, `hanmaum-science-institute`,
   `blackstone-belleforet-resort`
2. legacy 본문 목록: 블랙스톤을 제거한 나머지 5개
3. E2E 전체 경로 목록: 구조화 3개 + legacy 5개 = 8개
4. 블랙스톤 legacy 본문 fixture와 E2E snippet만 제거하고 나머지 값은 보존

**Rationale**: assertion을 삭제하거나 개수만 검사하면 어떤 작업물이 어느
형식인지 보호하지 못한다. feature 005 리뷰에서 `structuredSlugs` 갱신 누락으로
8개 중 7개 경로만 검증한 회귀가 있었으므로 목록과 총 길이를 함께 고정한다.

**Alternatives considered**:

- 목록 대신 개수만 검사: 기각. 누락과 잘못된 대체가 서로 상쇄될 수 있다.
- 블랙스톤 fixture assertion 삭제만 수행: 기각. 새 구조화 목록 계약이 없다.

## D-007. 검증된 데모가 없으므로 데모 요소를 만들지 않는다

**Decision**: 블랙스톤 상세에 `demo`를 설정하지 않는다.

**Rationale**: 인터뷰와 저장소 어디에도 검증된 공개 데모 주소가 없다. 선택
증거 부재를 빈 카드나 준비 중 문구로 채우지 않는 헌법 원칙을 따른다.

## D-008. E2E는 기존 dev 서버와 분리된 프로덕션 서버에서 검증한다

**Decision**: `pnpm run build` 후 별도 포트로 프로덕션 서버를 띄우는 임시
Playwright 설정을 사용하고 실행 후 삭제한다. `playwright.config.ts`의
`reuseExistingServer`에 의존하지 않는다.

**Rationale**: 포트 1104의 장기 실행 dev 서버가 `.next/dev` 잠금을 잡고 있어
두 번째 dev 서버를 띄울 수 없고, 기존 설정은 stale 서버를 재사용할 수 있다.
소스 변경이 반영되지 않은 서버로 통과하는 거짓 증거를 막아야 한다.

**Alternatives considered**:

- 포트 1104 서버 재사용: 기각. 변경 반영 여부를 보장하지 못한다.
- 두 번째 dev 서버 실행: 기각. `.next/dev` 잠금 때문에 시작되지 않는다.
