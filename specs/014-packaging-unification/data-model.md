# Data Model: 패키징 단일화

**Feature**: 014-packaging-unification

이 기능은 데이터베이스나 영속 엔티티를 도입하지 않는다. 모델링 대상은
스크립트 간에 주고받는 상태 하나와, 기존 판정에 이름을 붙인 개념 둘이다.

## 1. 준비 결과 요약 (신규)

**목적**: 하위 단계의 실행 결과를 `bootstrap` 이 취합해 한 번에 보고한다
(FR-017). stdout 파싱 대신 파일을 쓰는 이유는 research R5 참조.

**위치**: `.harness/state/bootstrap-summary`

**수명**: `bootstrap` 시작 시 삭제 → 각 단계가 append → 7단계 끝에 읽고 삭제.
`.harness/state/` 는 git-ignored 이므로 커밋되지 않는다.

**형식**: 한 줄에 하나의 항목, `<종류> <값>` (탭 없이 공백 1개 구분).
파싱을 단순하게 유지하기 위해 값에 공백을 넣지 않는다.

| 종류 | 값 | 기록 주체 | 예 |
|---|---|---|---|
| `version` | `<이전>-><이후>` 또는 `unchanged:<버전>` | `pkg-sync.sh` | `version 1.1.4->1.2.0` |
| `reclaimed` | 정수 (인덱스에서 회수한 파일 수) | `reclaim-shared.sh` | `reclaimed 9` |
| `doctor` | `<fail 수>/<warn 수>` | `doctor.sh` | `doctor 0/2` |

**규칙**:
- 같은 종류가 여러 번 기록되면 마지막 것을 쓴다 (단계 재실행 대비).
- 파일이 없거나 비어 있으면 요약을 "변경 없음" 으로 출력한다.
- 알 수 없는 종류는 무시한다 — 구버전 스크립트와 섞여도 깨지지 않아야 한다.

**검증**: 형식이 어긋난 줄은 무시하고 나머지를 처리한다. 요약 출력이
`bootstrap` 을 실패시키지 않는다 (보고 기능이 준비 자체를 막으면 안 된다).

## 2. 배포 모드 (기존 개념, 이름 부여)

레포가 하네스를 받는 방식. 기존에 여러 스크립트가 각자 판정하던 것을 하나의
개념으로 정리한다.

| 값 | 판정 | 의미 |
|---|---|---|
| `lock` | `harness.lock` 존재 | 버전 캐시 + 심링크 구조 |
| `copy` | `harness.lock` 없음 | upstream 파일이 레포에 복사됨 |

**상태 전이**: `copy → lock` 은 `migrate` 로 일방향. 역방향 전이는 지원하지
않는다 (되돌리려면 커밋을 되돌린다).

**소비처**: 런처 자가 부트스트랩(`harness:11`), `pkg-sync.sh:11`,
`migrate.sh:65`, `update.sh` 의 lock 가드, 그리고 이번에 추가하는
`doctor` 보고 (FR-008).

## 3. 준비 상태 (기존 개념, 이름 부여)

`doctor` 가 이미 검사하는 것들을 사용자 관점 네 값으로 묶은 것. 새 저장소나
새 판정 로직을 만들지 않는다 — 요약 출력에서 쓰는 어휘다.

| 값 | 조건 | 사용자에게 필요한 조치 |
|---|---|---|
| 정상 | doctor fail 0 | 없음 |
| 일부 소실 | 공유 경로 링크 누락 | `bootstrap` 재실행 |
| 버전 불일치 | lock 채널과 `current` 불일치 | `bootstrap` 재실행 |
| 미전환 | 배포 모드가 `copy` | `migrate` 후 커밋·푸시 |

## 관계

```
배포 모드 ──(copy 일 때)──> 은퇴 예고 표시 (FR-006/007)
    │
    └──> doctor 보고 (FR-008)

pkg-sync ─┐
reclaim  ─┼─> 준비 결과 요약 ──> bootstrap 요약 출력 (FR-017)
doctor   ─┘
```
