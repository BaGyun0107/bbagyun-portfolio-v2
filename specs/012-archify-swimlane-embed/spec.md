# Feature Specification: Archify 스윔레인 임베드 전환

**Feature Branch**: `chore/cleanup-downstream-harness`

**Created**: 2026-09-10

**Status**: Complete

**Input**: 사용자 승인 설계에 따라 호텔 예약 시스템의 작은 스윔레인과 크게 보기를 실제 Archify 결과로 전환한다. 현재 포트폴리오 카드 구조와 색상 체계를 유지하고, 작은 보기에서는 핵심 구조만, 크게 보기에서는 세부 설명과 관계 문구까지 제공한다. 별도 Viewer 기능과 새 탭 동작은 제거하며 테스트 작업은 TDD로 포함한다.

## Context

Feature 011은 호텔 예약 시스템의 `플랫폼 변경·검증·배포 흐름`을 기존 스윔레인과 별도로 열어 비교하는 Archify 파일럿을 완성했다. 사용자는 Archify가 만든 node·관계·화살표와 배치 품질은 승인했지만, standalone 화면의 검색·내보내기·테마·프레젠테이션 등 많은 기능은 포트폴리오 독자에게 필요하지 않다고 판단했다.

이 후속 기능은 현재 카드와 `크게 보기` 경험 안에 실제 Archify 결과를 배치한다. 별도의 설계 목업이나 재작성한 유사 다이어그램을 사용하지 않으며, 승인된 10개 단계와 12개 관계의 의미를 바꾸지 않는다.

### Visual Evidence Decision

- **Visual decision: provided** — 여러 경계와 복구 흐름을 함께 읽어야 하므로 스윔레인을 유지한다.
- **Existing visual disposition: replace pilot renderer for one target** — 호텔 예약 시스템 한 건의 작은 보기와 크게 보기만 실제 Archify 표현으로 전환한다.
- 포트폴리오 카드, 전체 흐름 설명과 예외 대응은 유지한다.
- 다른 작업물의 기존 스윔레인은 이번 범위에서 전환하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 독자가 카드에서 핵심 구조를 빠르게 파악한다 (Priority: P1)

호텔 예약 시스템 작업물을 읽는 독자는 현재 포트폴리오와 어울리는 작은 스윔레인에서 전체 단계 배치와 분기·복구 구조를 먼저 파악할 수 있다. 좁은 화면에서 단계명과 세부 문구를 판독하는 책임은 기존 `크게 보기`가 맡는다.

**Why this priority**: 작은 보기의 정보 과밀을 줄이면서도 다이어그램이 전달하는 구조적 증거를 잃지 않는 것이 전환의 핵심 가치다.

**Independent Test**: 호텔 예약 시스템 상세에서 작은 스윔레인을 확인해 승인된 모든 단계와 관계의 위치 및 단계명 요소가 유지되고 세부 설명과 관계 문구는 숨겨졌는지 확인한다. 좁은 화면에서는 `크게 보기`를 열어 같은 단계명과 세부 문구를 판독할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 호텔 예약 시스템의 대상 스윔레인, **When** 독자가 작은 보기를 읽는다, **Then** 승인된 단계와 정상·분기·복구 구조를 한눈에 구분할 수 있다
2. **Given** 작은 보기의 제한된 공간, **When** 다이어그램이 표시된다, **Then** 단계명 요소와 전체 topology는 삭제되지 않고 세부 설명과 관계 문구는 표시되지 않으며 좁은 화면의 문구 판독은 `크게 보기`가 담당한다
3. **Given** 현재 포트폴리오의 밝은 또는 어두운 화면, **When** 작은 보기가 표시된다, **Then** 카드·본문·경계·예외 색상이 주변 콘텐츠와 같은 시각 체계를 따른다
4. **Given** 작은 보기, **When** 독자가 pointer 또는 keyboard로 접근한다, **Then** 다이어그램 내부의 별도 탐색 도구가 활성화되지 않는다

---

### User Story 2 - 독자가 같은 흐름을 크게 열어 세부 내용을 읽는다 (Priority: P1)

독자는 기존 `크게 보기`를 사용해 작은 보기와 같은 배치에서 단계 세부 설명과 의미 있는 관계 문구를 읽을 수 있다.

**Why this priority**: 작은 보기에서 줄인 정보를 별도 제품형 Viewer가 아니라 현재 포트폴리오의 익숙한 Dialog 안에서 복원해야 한다.

**Independent Test**: `크게 보기`를 mouse, touch와 keyboard로 열어 작은 보기와 같은 단계·관계 배치, 세부 설명과 관계 문구를 확인하고 닫은 뒤 원래 동작으로 초점이 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 대상 스윔레인 카드, **When** 독자가 `크게 보기`를 활성화한다, **Then** 현재 포트폴리오 Dialog 안에 같은 다이어그램의 상세 표현이 열린다
2. **Given** 상세 표현, **When** 독자가 단계와 관계를 읽는다, **Then** 단계 세부 설명과 모든 의미 있는 관계 문구를 확인할 수 있다
3. **Given** 열린 상세 표현, **When** 독자가 화면을 살핀다, **Then** 검색·내보내기·테마 선택·프레젠테이션·확대·축소·관계 추적 동작이 표시되지 않는다
4. **Given** 열린 Dialog, **When** 독자가 닫기 또는 Escape를 사용한다, **Then** Dialog가 닫히고 초점이 `크게 보기`로 돌아온다

---

### User Story 3 - 기존 포트폴리오 경험과 실패 안전성이 유지된다 (Priority: P2)

독자는 Archify 자료의 준비 상태와 관계없이 전체 흐름 설명과 예외 대응을 읽을 수 있고, 자료를 표시할 수 없을 때도 빈 영역 대신 기존 스윔레인으로 흐름을 확인할 수 있다.

**Why this priority**: 생성된 시각 자료 하나의 실패가 작업물 전체의 이해나 다른 작업물의 검증된 경험을 깨뜨리면 안 된다.

**Independent Test**: 정상 자료와 사용할 수 없는 자료 조건을 각각 확인해 정상 조건에서는 실제 Archify 결과가 보이고 실패 조건에서는 기존 스윔레인이 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 대상 자료, **When** 작은 보기와 크게 보기를 연다, **Then** 둘 다 같은 승인 원본에서 생성된 실제 Archify 결과를 사용한다
2. **Given** 대상 자료가 없거나 올바른 다이어그램이 아닌 상태, **When** 카드가 표시된다, **Then** 빈 영역 없이 기존 스윔레인이 대신 표시된다
3. **Given** 시각 자료의 성공 또는 실패 상태, **When** 독자가 카드 본문을 읽는다, **Then** 전체 흐름 설명과 예외 대응은 항상 유지된다
4. **Given** Archify 자료가 없는 다른 작업물, **When** 독자가 해당 스윔레인을 사용한다, **Then** 현재 작은 보기와 크게 보기 동작이 그대로 유지된다

---

### User Story 4 - 소유자가 전환의 사실성과 범위를 검증한다 (Priority: P2)

포트폴리오 소유자는 새 표현이 기존 파일럿의 실제 결과를 사용하고, 원본 의미·공개 문구·다른 작업물의 표현을 변경하지 않았다는 근거를 확인할 수 있다.

**Why this priority**: 시각 통합을 위해 검증된 결과를 다시 그리거나 승인되지 않은 의미를 추가하면 포트폴리오 증거의 신뢰성이 떨어진다.

**Independent Test**: 선행 원본·결과물과 새 작은 보기·상세 보기를 대조해 단계·관계·방향의 불일치, 공개 문구 변경과 다른 작업물 전환이 없는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Feature 011의 승인 원본과 결과물, **When** 새 표현과 대조한다, **Then** 단계 10개와 관계 12개의 누락·추가·방향 불일치가 없다
2. **Given** 포트폴리오에 표시된 다이어그램, **When** 제작 근거를 확인한다, **Then** 설계 목업이 아니라 검증된 실제 Archify 결과를 사용했음을 확인할 수 있다
3. **Given** 전환 전후의 작업물 콘텐츠, **When** 공개 문구를 대조한다, **Then** 제목·목적·전체 흐름 설명·예외 대응과 연결 인사이트의 사실 변경이 없다
4. **Given** 이번 파일럿 완료, **When** 다른 스윔레인의 전환 여부를 판단한다, **Then** 자동 확장하지 않고 별도의 사용자 승인과 후속 기능을 요구한다

### Edge Cases

- 작은 화면에서 단계 이름이 읽기 어려울 정도로 축소되면 어떻게 되는가? → 실제 Archify 전체 topology와 무스크롤 원칙을 유지하는 구조 미리보기로 사용하고, 단계명과 세부 문구의 판독은 기존 `크게 보기`에서 제공한다.
- 밝은 화면과 어두운 화면 전환 중 원래 Viewer 색상이나 도구가 잠깐 보이면 어떻게 되는가? → 포트폴리오 표현 준비가 끝날 때까지 자료를 공개하지 않는다.
- 시각 자료는 응답했지만 예상한 다이어그램 구조가 없으면 어떻게 되는가? → 성공으로 보지 않고 기존 스윔레인으로 대체한다.
- 자료 준비가 끝나지 않으면 어떻게 되는가? → 제한 시간 뒤 기존 스윔레인으로 대체하고 빈 로딩 상태를 남기지 않는다.
- 작은 보기와 크게 보기의 정보 밀도 때문에 서로 다른 흐름으로 보이면 어떻게 되는가? → 단계·관계·배치는 동일하게 유지하고 세부 설명의 표시 여부만 다르게 한다.
- 내부 탐색 동작이 숨겨졌지만 keyboard로 여전히 접근할 수 있으면 어떻게 되는가? → 숨김 상태만으로 완료하지 않고 내부 탐색 대상이 실제 Tab 순서에서 제외됐는지 확인한다.
- 생성 결과를 표시하기 위한 색상 변환이 정상·예외 의미를 흐리면 어떻게 되는가? → 예외는 색상과 점선을 함께 사용하고 외부 설명을 유지한다.
- 선행 결과물의 원본이나 생성 파일을 변경해야만 통합할 수 있으면 어떻게 되는가? → 해당 방식은 사용하지 않고 선행 결과물을 수정하지 않는 표시 계층에서 해결한다.
- 다른 작업물의 스윔레인이 선택 정보를 갖지 않으면 어떻게 되는가? → 새 wrapper나 placeholder 없이 현재 표현을 유지한다.
- 상세 Dialog가 닫혔다 다시 열리면 어떻게 되는가? → 동일한 상세 밀도와 테마를 다시 준비하고 이전 내부 탐색 상태는 유지하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

#### 파일럿 범위와 사실 보존

- **FR-001**: 전환은 `hotel-reservation-platform`의 `platform-change-verification-deployment` 한 건에만 적용되어야 한다
- **FR-002**: 작은 보기와 크게 보기는 Feature 011에서 검증된 실제 Archify 결과를 사용해야 한다
- **FR-003**: 설계 목업이나 별도로 다시 그린 유사 다이어그램을 공개 결과로 사용하지 않아야 한다
- **FR-004**: 기존 단계 10개와 관계 12개의 ID, 의미, 방향과 정상·분기·복구 구조를 유지해야 한다
- **FR-005**: 제목, 목적, 전체 흐름 설명, 예외 대응과 연결 인사이트의 공개 문구를 변경하지 않아야 한다
- **FR-006**: 다른 작업물의 스윔레인은 별도 승인 없이 전환되지 않아야 한다
- **FR-007**: 선행 Archify 의미 원본과 생성 결과물을 직접 수정하지 않아야 한다

#### 작은 보기와 크게 보기

- **FR-008**: 작은 보기는 승인된 모든 단계와 관계의 배치를 유지해야 한다
- **FR-009**: 작은 보기에는 단계명 요소와 전체 관계 구조가 삭제 없이 표시되어야 하며, 좁은 화면에서 단계명과 세부 문구를 판독하는 책임은 기존 `크게 보기`가 가져야 한다
- **FR-010**: 작은 보기에는 단계 세부 설명과 관계 문구가 표시되지 않아야 한다
- **FR-011**: 크게 보기는 작은 보기와 같은 단계·관계 배치를 사용해야 한다
- **FR-012**: 크게 보기에는 단계 세부 설명과 모든 의미 있는 관계 문구가 표시되어야 한다
- **FR-013**: 기존 `크게 보기` 이름과 Dialog 동작을 유지해야 한다
- **FR-014**: 별도의 Archify 보기 동작과 새 탭 연결을 공개하지 않아야 한다
- **FR-015**: 검색, 내보내기, 테마 선택, 프레젠테이션, 확대·축소, 관계 추적과 내부 단축키를 작은 보기와 크게 보기에서 제공하지 않아야 한다

#### 시각 통합과 접근성

- **FR-016**: 다이어그램의 배경, lane, node, 문구, 경계와 관계선은 현재 포트폴리오의 시각 체계와 일치해야 한다
- **FR-017**: 정상 흐름은 현재 기본 글자·경계 색상을 사용하고 예외 흐름은 현재 오류 색상과 점선을 함께 사용해야 한다
- **FR-018**: 기술 종류별 별도 색상 범례를 만들지 않아야 한다
- **FR-019**: 밝은 화면과 어두운 화면 전환을 다이어그램 재로딩 없이 반영해야 한다
- **FR-020**: 준비되지 않은 원래 Viewer 색상이나 도구가 사용자에게 노출되지 않아야 한다
- **FR-021**: 시각 자료는 의미 있는 제목과 전체 흐름 설명을 보조기술에 제공해야 한다
- **FR-022**: 시각 자료 내부의 탐색 대상은 pointer와 keyboard로 활성화되지 않아야 한다
- **FR-023**: 기존 `크게 보기`의 mouse·touch·keyboard 활성화, 닫기와 초점 복귀가 유지되어야 한다
- **FR-024**: 관계 차이는 색상만이 아니라 방향, 구조, 선 종류와 외부 텍스트로 구분되어야 한다

#### 실패·성능·검증

- **FR-025**: 자료를 불러오지 못하거나 유효한 다이어그램을 찾지 못하거나 준비 제한 시간을 넘기면 기존 스윔레인으로 대체해야 한다
- **FR-026**: fallback 상태에서도 전체 흐름 설명과 예외 대응을 유지해야 한다
- **FR-027**: 작은 보기 자료는 독자가 해당 영역에 가까워질 때 준비해야 한다
- **FR-028**: 크게 보기 자료는 독자가 Dialog를 열 때 준비해야 한다
- **FR-029**: 작은 보기와 상세 보기를 페이지 진입 시 동시에 불필요하게 준비하지 않아야 한다
- **FR-030**: 저장된 자료 경로는 같은 출처의 허용된 정적 문서로 제한되어야 한다
- **FR-031**: 작은 보기와 크게 보기의 정보 밀도 차이, 테마, 내부 상호작용 차단과 fallback을 자동 검사해야 한다
- **FR-032**: 지원 화면 폭의 가로 넘침, Dialog focus와 다른 작업물 회귀를 실제 브라우저에서 검사해야 한다
- **FR-033**: 구조 검사, 생성 근거, 실제 브라우저 결과와 이미지 검토를 서로 구분해 기록해야 한다
- **FR-034**: 다른 스윔레인 전환은 이 파일럿의 사용자 화면 확인과 별도 승인을 요구해야 한다

### Key Entities

- **대상 스윔레인**: 호텔 예약 시스템에 공개된 플랫폼 변경·검증·배포 흐름이다. 기존 텍스트 설명과 fallback 데이터의 사실 기준이다.
- **Archify 의미 원본**: 승인된 10개 단계와 12개 관계를 보존하는 편집 가능한 원본이다.
- **Archify 생성 결과**: 의미 원본에서 생성되고 선행 검증 근거와 연결된 실제 다이어그램 문서다.
- **작은 표현**: 전체 배치를 유지하면서 단계 이름과 구조에 집중하는 제한 밀도 표현이다.
- **상세 표현**: 같은 배치에서 단계 세부 설명과 관계 문구를 복원한 Dialog 표현이다.
- **표시 상태**: 준비 중, 작은 표현 준비 완료, 상세 표현 준비 완료 또는 기존 스윔레인 fallback 중 하나다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대상 카드의 작은 보기와 크게 보기에서 승인된 단계 10개와 관계 12개의 누락·추가·방향 불일치가 0건이다
- **SC-002**: 작은 보기에서 단계명 요소의 누락은 0건이고 단계 세부 설명과 관계 문구의 노출은 0건이며, 좁은 화면의 `크게 보기`에서 단계명과 세부 문구를 확인할 수 있다
- **SC-003**: 크게 보기에서 승인된 단계 세부 설명과 의미 있는 관계 문구의 누락은 0건이다
- **SC-004**: 대상 카드에서 별도 Archify 동작, 새 탭 연결과 Viewer 탐색 도구의 노출은 각각 0건이다
- **SC-005**: 밝은 화면과 어두운 화면 모두에서 포트폴리오 색상 체계를 벗어난 기술 종류별 node 색상은 0건이다
- **SC-006**: 작은 보기와 크게 보기의 내부 탐색 대상으로 pointer 또는 keyboard focus가 이동하는 경우는 0건이다
- **SC-007**: 320px, 768px, 1024px, 1440px의 대상 작업물에서 문서 전체 가로 넘침과 카드 제목·동작·다이어그램 겹침이 각각 0건이다
- **SC-008**: 기존 `크게 보기`의 mouse·touch·keyboard 활성화, Escape 닫기와 trigger 초점 복귀 검사가 모두 통과한다
- **SC-009**: 자료 누락·잘못된 구조·준비 제한 시간 조건에서 빈 영역은 0건이고 기존 스윔레인 fallback 성공률은 100%다
- **SC-010**: 다른 작업물 스윔레인의 시각·동작·공개 문구 변경은 0건이다
- **SC-011**: 선행 의미 원본과 생성 결과물의 식별값이 Feature 011 검증 기록과 100% 일치한다
- **SC-012**: 구조 검사, 생성 근거, 실제 브라우저 검사와 이미지 검토가 한 검증 기록에서 모두 추적 가능하다

## Assumptions

- Feature 011의 Archify 의미 원본과 생성 결과물은 이번 기능의 승인된 시각 기준이다.
- 사용자는 현재 카드 구조, 작은 보기의 제한 밀도, 크게 보기의 상세 밀도와 A1 색상 규칙을 승인했다.
- 작은 보기와 크게 보기의 차이는 세부 정보 표시 여부뿐이며 topology를 별도로 만들지 않는다.
- 사용자가 승인한 A 정책에 따라 작은 보기는 화면 폭과 관계없이 실제 Archify 전체 topology를 무스크롤 구조 미리보기로 유지하고, 좁은 화면의 문구 판독은 `크게 보기`가 담당한다.
- 시각 자료 내부의 탐색 기능을 제거해도 기존 전체 흐름 설명과 예외 대응이 충분한 텍스트 대안을 제공한다.
- 현재 파일럿 한 건에서는 self-contained 결과물의 크기를 허용하고 다수 전환 시 성능 전략을 다시 검토한다.
- 앱 실행과 공개 화면은 Archify 제작 도구 설치에 의존하지 않는다.
- 기존 사용자 소유 개발 서버는 임의로 종료하거나 재시작하지 않으며 최종 검증은 별도 production 환경에서 수행한다.
- 저장소 전역 lint baseline과 관련 없는 파일 포맷은 이번 기능 범위에 포함하지 않는다.
