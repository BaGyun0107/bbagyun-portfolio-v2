Cloudflare Tunnel 인사이트의 시각 자료 범위

작업물의 CI/CD 실행 스윔레인을 반복하지 않고, 이 인사이트만의 질문을 가장 잘 설명하는 안을 골라주세요.

2026.04 초기
GitHub Actions → WAF 차단 ✕
↓ 예외 적용
같은 hostname → connector A / B
└ 잘못된 방향 → SSH 실패
2026.05 이후
Actions → Access → Bastion
├ PermitOpen → 서버 A
└ PermitOpen → 서버 B

A. 실패에서 현재 구조까지

초기 WAF·connector 문제와 Bastion 전환을 한 흐름으로 비교합니다. 문제 해결과 설계 발전이 함께 보입니다.

GitHub Actions
↓ Service Token
Cloudflare Access
↓ Bastion SSH key
Bastion / nologin / PermitOpen
↓ project × server key
배포 서버

B. 현재 다중 보안 경계

현재 운영 구조의 인증 계층에 집중합니다. 초기 트러블슈팅은 본문 산문으로만 남깁니다.

C. 재사용과 분리의 기준

무엇을 공용으로 재사용하고 무엇을 서버별로 분리했는지 보여줍니다. 운영 모델은 선명하지만 사건의 흐름은 약합니다.
