# Claude Code Harness

The common team rules load from `AGENTS.md` through the bare import on the
first line — do not duplicate them here. This file carries only Claude
Code-specific wiring; keep it a thin entrypoint per
`.harness/policies/context-engineering.md`.

## Claude-Specific Wiring

- Launcher: prefer `./harness claude`. It runs the shared agent preflight,
  and a SessionStart hook runs
  `.harness/scripts/setup/update-check.sh --background` (heavy daily/weekly
  work runs detached; notices surface on a later run).
- Skill suggestions: the UserPromptSubmit hook in `.claude/settings.json`
  runs `.harness/hooks/skill-injector.mjs`, which *suggests* skills via
  keyword matching (suggestion only, not enforced).
- Merged skills: Claude Code reads shared skills through `.claude/skills`,
  generated by `./harness skills-link` from `.harness/skills` and
  `.harness/skills-local`.
- Decision stops: the notify-decision rule lives in `AGENTS.md`; Claude also
  has a Stop hook that attempts `./harness notify-decision` automatically
  when the final answer is a decision question.

## Claude-Native Rule Mirrors (`.claude/rules`)

Always loaded: `phase-routing.md` (Medium+ Hard Gate, Plan-of-Record Gate),
`skill-ownership.md`, `work-safety.md`, `e2e-validation.md`,

files are read). Each mirrors `.harness/policies/*` and
names its Codex-side counterpart where one exists.
