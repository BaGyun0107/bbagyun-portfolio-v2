# Jenkins에서 GitHub Actions matrix로 전환한 인사이트 인터뷰

- 인터뷰 일자: 2026-08-27
- 대상 인사이트: `jenkins-retirement-and-github-actions-migration`
- 연결 작업물: `codi-harness-dx-platform`
- 상태: 공개 문안 승인 완료

## 재사용한 기존 확정 사실

- GitHub Actions workflow와 하네스 CI/CD 구조를 직접 설계·구현했다.
- 기존 Jenkins의 `codi-rs-module` 배포는 slave 1개에서 호텔별로 순차 실행됐다.
- 호텔별 배포는 약 3분, 다섯 호텔 전체는 약 15분이 걸렸다.
- GitHub Actions matrix 적용 뒤 다섯 호텔 전체 배포 화면에서 약 3분을 확인했다.
- 위 시간은 반복 실험 평균이 아니라 기존 Jenkins와 GitHub Actions 실행 화면을 비교한 관찰값이다.
- 월 `$151.84`는 2026-08-20 AWS 서울 리전 Linux On-Demand `t3.large` 2대와 월 730시간의 공개 가격으로 계산한 컴퓨팅 추정치다. 과거 실제 청구액이 아니며 스토리지·네트워크·세금은 제외한다.
- 2026-08-20 사용자 보고 기준 GitHub Actions 무료 티어를 초과하지 않았지만 향후 무료를 보장하지 않는다.

## 이번 인터뷰에서 확정한 답변

### 핵심 메시지

배포 도구 교체보다 단일 Jenkins slave의 순차 대기열을 대상별 matrix job으로 나누어 병목을 줄인 경험을 전면에 둔다.

### 실제 구현

현재 `codi-rs-module`은 변경 파일을 기준으로 배포 대상 플랫폼을 계산하고, 계산된 배열을 GitHub Actions matrix에 전달해 플랫폼별 재사용 workflow를 병렬 실행한다.

- 공통 코드 변경: 다섯 호텔 전체
- 호텔별 코드 변경: 해당 호텔
- 계산된 대상: 플랫폼별 matrix job

호텔마다 독립된 최상위 workflow를 수동 관리하는 구조가 아니다.

### 시간 경계

Jenkins에서 GitHub Actions로의 마이그레이션은 다른 프로젝트부터 먼저 시작했다. 공통 코드, 다섯 호텔별 코드·환경변수·배포 대상이 한 저장소에 있는 `codi-rs-module`은 구조가 복잡해 거의 마지막에 진행했다.

Git 이력에서 경로 감지와 platform matrix는 2026-07-01, 공통 pipeline과 재사용 workflow 통합은 2026-07-07로 확인했다. 공개 인사이트 날짜는 현재 구조가 통합된 `2026-07-07`로 변경한다. 약 15분에서 약 3분으로 줄어든 관찰은 이 프로젝트에 matrix 배포 단위를 적용한 뒤의 결과다.

### 실패 격리 경계

`fail-fast: false`는 한 호텔 job의 실패가 다른 호텔 job을 즉시 취소하지 않도록 의도한 설계다. 그러나 특정 호텔 job을 의도적으로 실패시키거나 운영 실패 사례에서 다른 호텔 완료 여부를 대조하지 않았다. 설정과 실행 구조의 의도로만 공개하고 검증된 장애 격리 성과로 주장하지 않는다.

### 비용 비중

Jenkins 비용은 전환 배경에서 한 번만 언급한다. `$151.84` 추정치를 성과 전면이나 실제 절감액으로 사용하지 않고, 결과 영역은 약 15분에서 약 3분으로 바뀐 실행 화면 관찰에 집중한다.

### 회고와 적용 경계

핵심 회고는 “도구보다 배포 단위가 중요하다”이다. 대상 사이에 배포 순서가 필요하거나 변경 코드가 어느 대상에 영향을 주는지 정확히 계산할 수 없으면 같은 방식의 병렬화를 피한다.

### 실제로 검토하지 않은 대안

Jenkins slave·executor 확장은 검토하지 않았다. 기존 Jenkins 설정을 직접 담당하지 않았고, 다른 프로젝트의 GitHub Actions 마이그레이션을 진행하며 비용과 운영 측면에서 GitHub Actions가 더 적합하다고 판단한 뒤 Jenkins 확장을 대안으로 두지 않았다.

### 역할 공개 경계

기존 Jenkins 구성은 직접 설계한 영역이 아니며, 마이그레이션과 GitHub Actions 배포 구조 설계부터 담당했다고 짧게 명시한다.

### 시각 자료

인사이트에는 Jenkins 순차 대기열과 GitHub Actions matrix 병렬 실행을 비교하는 before/after data-flow를 제공한다. 작업물의 기존 CI/CD 스윔레인은 현재 전체 실행 흐름을 유지하고, 인사이트는 배포 단위 변화만 보여 준다.
